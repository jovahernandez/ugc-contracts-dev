RESUMEN EJECUTIVO
-----------------
Se implementó un sistema completo de generación y firma de contratos para
creadores UGC, con integración automática a HubSpot mediante webhooks. El
sistema incluye tracking de metadata legal, expiración de links de firma, y
validación de seguridad.

------------------------------

1. TRACKING DE METADATA LEGAL Y SEGURIDAD (Fase 1)
   ✅ Captura de IP real del firmante (detrás de proxies/Render)
   ✅ Detección de timezone del firmante
   ✅ Timestamp preciso de firma
   ✅ Hash criptográfico del documento (SHA-256)
   ✅ Almacenamiento de metadata en archivo JSON

FLUJO COMPLETO AUTOMATIZADO
----------------------------

1. Usuario marca contacto en HubSpot con ready_to_generate = true
2. HubSpot dispara webhook a tu servidor en Render
3. Servidor valida firma del webhook (seguridad)
4. Servidor obtiene datos del contacto desde HubSpot
5. Servidor genera contrato DOCX automáticamente
6. Servidor crea token de firma con expiración de 5 días
7. Servidor guarda link de firma en HubSpot (contract_signed_link)
8. Servidor resetea ready_to_generate a false
9. Usuario copia link y lo envía al creador
10. Creador abre link, ve contrato, y firma
11. Sistema captura IP, timezone, timestamp, y hash del documento
12. Creador descarga PDF firmado


PROBLEMAS ENCONTRADOS Y SOLUCIONES
-----------------------------------

PROBLEMA 1: Validación de Firma del Webhook Fallaba
Síntoma: Webhook rechazado con "Invalid signature"
Causa raíz: Express parseaba JSON body antes de validar firma,
             destruyendo el raw body necesario para HMAC-SHA256
Solución: Implementar middleware express.json({ verify: ... }) para
          capturar raw body antes del parsing
Archivos modificados: src/server.ts, src/routes/webhookRoutes.ts
Estado: ✅ RESUELTO

PROBLEMA 2: Propiedad contract_link No Existía en HubSpot
Síntoma: Error 400 "Property contract_link does not exist"
Causa raíz: Nombre de propiedad incorrecto
Solución: Usar propiedad existente "contract_signed_link"
Archivo modificado: src/routes/webhookRoutes.ts línea 228
Estado: ✅ RESUELTO

PROBLEMA 3: Repositorio GitHub Público con URL del Webhook
Síntoma: URL del webhook visible en GitHub público
Riesgo: Potencial spoofing de webhooks si no hay validación
Solución 1: Habilitar validación de firma (crítico)
Solución 2: Convertir repositorio a privado (complementario)
Estado: ✅ RESUELTO (ambas soluciones implementadas)

VARIABLES DE ENTORNO CONFIGURADAS EN RENDER

  Descripción: Token de Private App de HubSpot para API calls
  Ubicación: Settings → Integrations → Private Apps → Show token

HUBSPOT_WEBHOOK_SECRET=****************
  Descripción: Secret compartido con HubSpot para validar firma v3
  Generado con: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  Importante: DEBE ser idéntico al configurado en HubSpot

PUBLIC_BASE_URL=https://ugc-contracts-dev.onrender.com
  Descripción: URL pública del servidor para generar links

SIGNATURE_EXPIRATION_DAYS=5
  Descripción: Días de vigencia del link de firma (opcional, default: 5)

API_AUTH_TOKEN=****************
  Descripción: Token para proteger endpoints manuales (opcional)

ARQUITECTURA
------------

Backend: Node.js + Express + TypeScript
Plantillas: Docxtemplater (DOCX)
Generación PDF: Puppeteer (fallback de CloudConvert)
Almacenamiento: Sistema de archivos local (storage/)
Deploy: Render (auto-deploy desde GitHub main branch)
CRM: HubSpot (webhooks + API v3)
Estructura:
  - storage/contracts/     → DOCX generados
  - storage/signatures/    → JSON con metadata de firmas
  - storage/signed/        → PDF firmados por creadores
